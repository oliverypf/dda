## 1. 状态与证据规则

- PENDING：尚无完整交付或本阶段证据。
- PARTIAL：已有基础实现、历史证据或部分交互，仍缺本包范围内的实现/验证。
- BLOCKED_EXTERNAL：具体子项依赖日历时间、人工签署或真实设备；其余可实施工作继续。
- VERIFIED：完成计划要求，证据明确对应当前候选，且没有未关闭的验收项。

当前 16 个有效工作包均为 PARTIAL、零 VERIFIED；PENDING 仍可用于尚未执行的具体场景。零 VERIFIED 只表示整包尚未完成，不等于包内功能全部未实现。表中统一区分“剩余实现／集成／验收缺口”，模拟已过、实现已有、实机待验分别描述。

“现有依据”均为基线，不自动代表阶段四已通过。“应补证据”是交付要求，不是已存在的报告。关闭时逐项填写证据路径、候选版本、执行日期和结论；完整规则见实施计划第 6 节。S4-13 Git 互验为 P1，S4-10 常驻 runtime 为 P2；包内维护性拆分不自动升级为安全阻断。
