# Windows Phase 1 存储迁移边界

状态：M1 实施中；已实现 SQLite 导入与校验，但完整迁移切换协议尚未完成。以下迁移约束仍是验收要求，不代表全部已实现。

当前 JSON/JSONL 数据属于前置版本事实源。Phase 1 以 hmcodex.db 为唯一事实源；现有文件不能作为数据库的并行写入后端。当前尚未完成数据库迁移，不得声明已经满足该约束。

## 当前可验证能力

- 默认 Harness 路径为 `hmcodex.db`；Phase 1 task、recovery、线程历史、dashboard、回放、Memory、Dream、插件、Evolution 和事件管理入口已逐步统一 SQLite 路径。仍需逐入口审计全部独立事实源。
- `harness-events import --source <file> --source-format trajectory-jsonl|harness-json --harness-event-store <target.db>` 校验旧数据，生成新事件并保留原事件 ID、原记录摘要及来源类型。SQLite 导入整批提交；墓碑插入失败会连同事件和回执回滚。源文件不修改。
- `checkpoint` 与 `restore` 生成新的 SQLite 文件并校验，不覆盖现有目标；恢复测试覆盖事件、回执和墓碑。
- 默认任务目录的迁移检查要求旧事件具有导入来源引用，并匹配 run、事件类型、聚合类型/ID 和 payload digest，或对应 run 已有删除墓碑。空数据库或仅复用来源引用但改变事实内容的事件不能作为已迁移证明。2026-09-07 迁移、checkpoint 和 Event Store 定向测试 19/19 通过；这不是完整迁移验收。

## 尚未完成的切换协议

- 来源**文件**摘要、迁移版本与持久化迁移进度；现有来源类型/记录摘要不能替代这些字段。
- 停止旧写入者与维护模式的跨进程强制互斥。
- 导入、完整性、全量回放通过后的原子切换标记，以及旧程序对该标记的拒绝打开机制。
- TaskRun 等其余独立 JSON store 的完整导入、引用重绑定和权威性收敛。
- 原文件、备份、projection 和缓存的统一删除/retention，防止删除内容从旧文件恢复。

上述缺口未完成前，不得把运行 `import` 成功视为整个数据目录已迁移，也不得宣称 M1 或 Phase 1 验收完成。

## 目标迁移约束

迁移必须在停止新任务、关闭旧写入者后进行。先验证源文件、记录文件摘要和只读备份，再将旧记录转换为带来源文件摘要、原记录标识、迁移版本的事件。缺失证据保持缺失标记，不生成虚拟事实填补。损坏文件进入诊断流程，禁止静默截断后继续导入。

以来源摘要和原记录标识作为导入幂等键；分批事务提交并保存进度。失败时继续使用未切换的旧版本，或保持维护模式；禁止一部分聚合写数据库、另一部分继续写旧文件。

完成导入、完整性和回放校验后，原子提交存储版本切换标记。Phase 1 启动遇到旧格式、未完成迁移、数据库损坏或不支持的版本时停止新任务，提供诊断和迁移入口，不自动回退到 JSON 写入。

切换后旧文件只供只读审计和用户管理，投影与缓存均从数据库重建。回退旧程序必须拒绝打开已切换的数据目录，避免形成分叉历史。原文件保留不代表可以绕过后续 retention、删除及 tombstone 要求。
