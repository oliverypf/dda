# Git 指纹误报：同模型修复实验

日期 2026-11-21。评分单位是一次独立尝试结束时留下的实现。一个客户端返回零退出码、一份看似正确的说明或诊断脚本跑绿，都不能代替行为验收。

## 题目与实验条件

- 从 dda `8aa4acd` 取出 193 个运行时源码文件、原 Git 审计测试中的前三个用例，添加最小 npm test 入口。各轮复制同一份已初始化的 Git 仓库。提交、提示与限额见 [protocol.json](protocol.json)。
- 每轮全新工作区和会话，无前轮补丁或提示。症状描述不含故障文件名或修改方法；仓库内保留已有回归测试。模型统一为官方 API 的 `deepseek-v4-flash`，响应报告 `deepseek-flash`，thinking 关闭。未向模型注入评分脚本。
- 代理逐轮执行相同上限：24 次模型请求、每次最多 4,096 个输出 token、累计 24,576 个输出 token、累计 2,500,000 字节原始请求体、480 秒墙钟。先到的上限生效。请求体还包括提示、工具描述和重发的历史，不等价于 token。usage 为服务端报告值。
- 采用各客户端原生工具循环。在授权工作区中允许读、写与测试。dda 使用 Windows 上的 CLI、受控执行和 JSONL 审批回执；租约配置列出 node、npm、git、rg 以及文件和测试能力。Pi 使用原生终端工具；DSH 使用 Windows workspace-write 沙箱。各宿主实际能否启动子进程存在差别。关闭 dda 的额外 Jev 服务以保持单模型，此设置直接影响其验证回退路径。
- 每轮结束后在评分目录重建源码，重新运行受保护的三个原始测试及三个独立检查：正常工作区刷新、真实暂存新文件、仓库配置改动。取外部行为结果，同时记录原测试是否改动。基线误报为红，暂存和配置保护为绿。[基线](seed-grade.json) · [判分脚本](grade.py) · [分轮结果](results.json)
- 判分器校准时曾把“暂存改动必须改变 metadataDigest”写成断言。设计中暂存可由独立 indexDigest 报告，故在评任何客户端前修正为断言实际越界判定。所有客户端使用同一版判分器。

三轮分类事件均为 `taskClass=test`，执行配置均为 `full-executor`。分类本身没有禁止写入，第 2 轮实际成功修改源码。现有记录也不能证明改一个分类标签就会成功。

同一句提示、尚未执行第一个工具时，三轮 dda 的首个请求体均为 178,672 字节，DSH 为 37,024 字节，Pi 为 6,220 字节。请求体包含系统提示、工具声明和其他字段；代理只记录总大小，各字段占比仍待测。这个差异直接影响客户端在同一累计输入字节上限内能做多少轮实验。

## 根因与改进顺序

对未修改种子逐个执行操作并独立取样。改工作区文件、单独运行 git status 均未使 metadataDigest 改变。首次创建 FETCH_HEAD 后该摘要改变，随后仅更新已有 FETCH_HEAD 的内容则保持不变。暂存真实改动后 indexDigest 改变，更新仓库配置后 metadataDigest 改变。原实现对易变文件忽略内容，但缺失和存在会序列化为不同结构。[六步探针结果](root-cause-probe.json) · [探针代码](probe.mjs)

1. **让失败断言约束下一次行动。** 将仍失败的测试、字段、最近改动和待区分的原因一起交给执行者。验收取本题第 2 轮：改了 untrackedDigest、原断言仍红时，应转向影响 metadataDigest 的输入，并能用一次最小探针区分文件创建与内容更新。
2. **拆开“修复”和“做测试”。** “修复并测试”的完成条件应同时包含产品改动和修后行为通过。测试结果已知为红时，在预算和权限仍允许的前提下，验证器不可用应保留不确定性，同时把下一项可执行检查交还执行者。不能把红灯判绿。
3. **让宿主和模型知道还剩什么预算。** 区分外部服务错误、输入预算耗尽和运行超时；接近限额时精简反复发送的工具说明与历史。对第 1 轮可用“首次有效修补前消耗的输入字节”和重复诊断轮数比较改造效果。

实验仅覆盖一个 Windows 故障和每客户端三次尝试。补丁通过这组行为检查不等于已通过 dda 的全套安全回归；各轮修改均留在独立实验工作区。
