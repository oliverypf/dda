## 宿主如何取得证据

失败断言有两个不透明的结果时，dda 会用已读且版本一致的源码定位候选生产者。它先在临时工作区重放当前失败，用原断言两侧的真实结果配对同一次运行中生产者收到的输入，只返回两份输入中不同的字段。模型在该断点的第一个请求中即可看到这份证据。候选补丁仍须在副本中通过原断言，成功落盘后还要在原工作区复测。[源码观测](../../../runtime/src/repair-candidate-workspace.mjs) · [断点和候选预检](../../../runtime/src/plugins/task-runner.mjs)

候选虽然用了不同的替换文本，却再现同一组输入差异时，宿主会在下一次请求中保留最近的拒绝回执和出现次数。源码未匹配与源码已匹配、行为仍失败分别有自己的回执。重复计数只描述被观测到的反例，后续候选仍要实际执行。[续修决策和回执](../../../runtime/src/repair-retest.mjs)

当前支持已核实的 Node ESM 单行二元断言，以及可以唯一定位的同步、单参数命名函数调用链。宿主用 Acorn 解析源码。多个生产者或多组输入均能解释一个结果时，会省略内部差异。上限、字段筛选和脱敏限制了回传数据；原断言和原测试仍按正常路径运行。[版本锁定](../../../runtime/package-lock.json) · [观测边界回归](../../../runtime/test/repair-candidate-workspace.test.mjs)

## 用上次失败的补丁校准

| 无模型校准 | 实际观测 | 结果 |
| --- | --- | --- |
| 同一错误断点，保留全部原代码 | `FETCH_HEAD.exists` 从 `false` 变为 `true`，`FETCH_HEAD.type` 从缺失变为 `"file"` | 原断言仍红，两侧输入能够唯一配对 |
| 上批第 3 次第 14 轮的错误候选 | 剩余差异为 `FETCH_HEAD.type` 的 `"absent"` 与 `"file"` | 拒绝，计数 1 |
| 上批第 3 次第 15 轮的另一份候选 | 测得同一组差异，候选文件哈希不同 | 拒绝，计数 2 |
| 更早的已知正确候选 | 两侧摘要相等，原断言通过 | 候选放行 |

## 正式对照条件

沿用上批的同一题目、同一错误工作区和同一模型 `deepseek-v4-flash`，关闭 thinking。各自在隔离工作区重放历史前八轮。历史补丁的部分工具参数以等效替换重建，进入真实模型前比对整个工作区哈希、原错误补丁和第 88 行的实际红测。每次余量为 16 个真实请求、711,126 字节进入预算代理的请求体、22,098 输出 token，单请求最多输出 4,096 token。每次从重放所得原红测开始，代理限时 413.746758 秒；原 launcher 的启动时刻没有精确日志，CLI 采用保守的 408 秒。新增的断点探测计入这段时间。[本次协议](protocol.json) · [运行入口](trial.py)
