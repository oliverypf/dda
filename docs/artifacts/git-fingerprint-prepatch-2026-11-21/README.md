## 续修路径

对已经读过源码、改动后复测仍然失败的目标，dda 会定位原断言。对于受支持的 `node --test <文件>` 目标，模型提交的 `file.patch` 或对已有文件的 `file.write` 会先生成候选内容。宿主将其放进临时工作区，在原断言行记录左右两次求值的结果，并调用原来的比较函数；每个操作数只求值一次。

- 断言失败时，模型得到实际观察到的两侧值，可以对仍在原版本上的文件继续提新补丁。未执行到断言、测试报错、超时、输出不完整或缺少可信回执，都不能授权写入。
- 断言满足且副本里的同一测试命令成功时，宿主按原有写入授权和源摘要检查落盘，随后自动在真实工作区复测。副本预验单独记账，不会充当原测试通过的证据。
- 当前接入单个 Node ESM 测试文件中单行的 `assert.equal`、`strictEqual`、`deepEqual`、`deepStrictEqual` 及相应否定比较。可见且可复制的工作区上限为 384 个条目、8 MiB，总体不含 Git 数据库和已安装的依赖。该路径使用现有的测试执行权限。复杂对象的回执只记录类型，原比较函数仍接收完整对象。[候选交付与复测](../../../runtime/src/plugins/task-runner.mjs) · [原断言与实测值](../../../runtime/src/repair-retest.mjs) · [候选工作区](../../../runtime/src/repair-candidate-workspace.mjs)

真实写入链路的非 Git 回归另行验证了不相等候选的拒绝、未执行到断言时保留原文件、沿用同一源摘要修正后成功落盘，以及宿主自动复测。13 个相关测试文件共 108/108 通过，含受控工具和工具注册表用例。[写入回归](../../../runtime/test/repair-candidate.test.mjs) · [工作区和断言回归](../../../runtime/test/repair-candidate-workspace.test.mjs)
