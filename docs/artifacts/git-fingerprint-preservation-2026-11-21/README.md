## 旧三份补丁的差别

原实现把元数据观察记在每个路径对应的条目中，这些条目一起进入 `metadataDigest`。它同时把各路径的链接判断合并为 `metadataLinkDetected`。已有一个链接时，第二个路径也变为链接，或者链接换到了另一条路径，全局标识仍为 `true`。此时对外可区分的信号来自逐路径摘要。

| 上一批补丁 | 普通刷新为什么通过 | 多链接时保留了什么 | 原六项 | 新增两项 |
| --- | --- | --- | --- | --- |
| [第 1 次](../git-fingerprint-feedback-2026-11-21/dda-1.patch) | 对易变路径在向 `entries[name]` 写入前 `continue` | 链接仅能置全局标识，没有对应的逐路径条目 | 6/6 | 0/2 |
| [第 2 次](../git-fingerprint-feedback-2026-11-21/dda-2.patch) | 缺失和普通文件在该路径都记为 `{volatile:true}` | 链接另记为 `{volatile:true,type:"link"}`，仍在自己的键下进入摘要 | 6/6 | 2/2 |
| [第 3 次](../git-fingerprint-feedback-2026-11-21/dda-3.patch) | 易变路径一律返回 `{}` | 路径键还在，但不同类型的值完全一样。另一次 `lstat` 只更新全局标识 | 6/6 | 0/2 |

上轮第 3 次的第 16 轮候选仍为链接保留了类型，当时未通过的是普通缺失与普通文件之间的差异。第 17 轮把易变条目统一改成 `{}` 才通过原断言。第 2 次也没有公开验证多链接，它保留了逐路径区分这一点由补丁与独立测试共同证实。[三份补丁的决策与工具调用](prior-decisions.md)

新评分器也在原种子和错误断点上校准，两者都保有链接检测，因此新增两项均通过。错误断点本身仍过不了工作树刷新相关的原测试和独立验收。[历史版本逐项成绩](multi-link/) · [上轮原六项判分](../git-fingerprint-feedback-2026-11-21/results.json)

## dda 如何决定是否写入

原断言只要求普通刷新前后的两个摘要相等。修复时，dda 先从断点记录还原改变了哪一个键，再检查原生产函数是否还通过同一摘要表达了需要区分的状态。对于能识别的逐键记录和布尔汇总代码，它在临时测试副本中重放三个受控输入：仅另一个键命中分支、两个键都命中、仅当前键命中。每种布局都会重复测量。只有原实现确实能在汇总值相同时区分新增和迁移两种变化，这项区别才成为本次补丁的写入条件。

候选必须同时通过原断言和这两项已观察到的区别。原断言通过但区别丢失时，模型收到具体的键、分支和失败的对照；已观察到的区别在候选上无法重测时，候选暂不写入。通过后仍在真实工作区复测原命令。这个检查目前覆盖能识别上述结构的 Node.js 代码。独立验收另用完整产品的公开接口测量。

把旧三份候选重新交给修改后的 dda，不请求模型也不改动产品，三者均通过原断言。新检查对第 1、3 份的新增和迁移都测得相同摘要并拒绝写入，对第 2 份都测得不同摘要并放行。[宿主对照脚本](guard-controls.mjs) · [三个写入判定与原始断言值](guard-controls.json)

## 独立验收

保留受保护的原测试三项和原独立验收三项。另在单独的临时仓库中通过产品公开的 `createGitObserver().snapshot()` 检查以下两个变化：

- `index` 已经是链接，再让 `FETCH_HEAD` 也成为链接。前后都必须报告有链接，元数据摘要必须变化。
- 从只有 `index` 是链接改为只有 `FETCH_HEAD` 是链接。两侧链接数量和全局标识都相同，元数据摘要仍须变化。

每项都有同一布局重复采样的稳定性对照，且保持文件字节、HEAD 和暂存指纹不变。评分器优先创建真实文件符号链接。本机 Windows 返回 `EPERM`，因此实际运行使用真实 Git 仓库及产品的公开观察器，只在文件系统读取边界替代指定文件的 `lstat` 类型。两项均实际执行。评分脚本与回执位于模型工作区以外。[独立测试](multi-link.test.mjs) · [评分入口](grade-links.mjs)
