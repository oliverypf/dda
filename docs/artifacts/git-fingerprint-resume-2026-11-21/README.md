## 实验起点和验收

起点取自上轮 dda 第 2 次运行。此前的补丁修改了 `runtime/src/execution-scope-snapshot.mjs`，原测试仍在 `git-audit.test.mjs:88:10` 比较两个 `metadataDigest` 时失败。错误工作区的运行时源码树 SHA-256 为 `9244e03181b45ada2259dc5dd9e7c09a63cd938fefc8723559ab25330a57a43c`。本轮在该工作区复现了退出码 1 和同一栈帧。独立检查中普通刷新仍红，真正暂存和配置变化均绿。[历史补丁](../git-fingerprint-retest-2026-11-21/dda-2.patch) · [历史评分与轨迹](../git-fingerprint-retest-2026-11-21/dda-2.json)

从相同断点启动三个独立会话，分别核对四件事。

1. **归因。** 从公开的模型说明、诊断命令的输出和源码改动中，辨别它是否定位到刷新前后参与指纹计算的具体差异。仅重复断言或从测试名猜测的情况单列。
2. **第二个产品补丁。** 核对模型接手后发生的写入，以及最终实现相对于错误状态的 diff。诊断脚本、临时日志和更改验收测试分别记录。
3. **原测试。** 从原生进程回执定位修后首次同目标绿测。另用受保护的原测试重建评分。
4. **独立验收。** 运行原判分器，核对正常刷新、真实暂存、配置变化以及测试文件完整性。CLI 的结束状态单列。[原判分器](../git-fingerprint-2026-11-21/grade.py)

上轮模型在错误复测时已用掉 8 次请求、1,788,874 个请求字节和 2,478 个输出 token，仅余 711,126 个请求字节。随后两次调用都用来回读此前已读的测试，未留下第二个产品补丁。这次三轮在错误断点开始计量真实模型预算，应分别对照当时的剩余字节和本次完整预算。[旧轨迹分析](../git-fingerprint-retest-2026-11-21/README.md)

## 如何还原断点和对齐预算

三份干净工作区均从种子 `0bdc700` 复制。回环代理按原 dda 第 2 次历史前八轮的公开答复和工具选择，驱动原生读取、写入、语法检查和目标测试。历史代理对原补丁工具参数只存前 750 字符，重放时从种子和错误工作区重建了一次等效替换。三次都验证了落盘字节、全工作区摘要、真实工具生成的补丁、目标测试退出码 1，以及宿主发出的 `failed_after_edit` 事件。第 9 个请求才转发给真实模型。对重放包只做了本地统计，三个会话各有 **600,630 字节**，未向上游发送。[重放程序](replay.py) · [哈希与协议](protocol.json)
